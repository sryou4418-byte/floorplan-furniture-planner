## 최신 확정 범위 — 이전 후보 목록보다 우선

사용자가 이후 논의에서 다음 버전을 **데스크톱 중심 7개 항목**으로 확정했다.
1. B1 도면 밖 가구 유실 방지.
2. B2 복사 이름 숫자 구분.
3. B3 말미 구분 번호·양끝 공백을 무시한 개수 집계.
4. 간격 표시.
5. 정렬 보조.
6. 가구 옆 빠른 편집창과 더블클릭 편집.
7. 빈 도면 우클릭 → 샘플 가구 추가.

**모바일 관련 수정·UI 재구성은 다음 버전에서 제외한다.** 기존 모바일 기능을 삭제하는 뜻이 아니다. B4 적용 실패는 미해결로 보존하고 후속 모바일 버전으로 미룬다. 실행 취소·다시 실행, 목록 잠금, 일괄 반복 배치, DB 업로드·재고·출력도 후순위다. 공통 코드 변경으로 기존 모바일 기능을 의도적으로 없애지 않는다.

### D1. 간격 표시 — 확정

- 데스크톱에서 선택하거나 이동 중인 가구와 가까운 벽·가구 사이 간격을 정수 mm로 표시한다.
- 선택한 가구 주변의 필요한 선만 보여 도면을 복잡하게 만들지 않는다.
- 겹침을 양의 빈 간격으로 오해하게 표시하지 않는다. 원형·회전된 사각형의 측정 기준을 명확히 정하고 기록한다.
- 화면 확대와 독립된 실제 mm로 계산하고 내부 정밀도는 보존한다.

### D2. 정렬 보조 — 확정

- 가구 가장자리·중심이 맞으면 안내선을 표시하고 가까운 위치에서 스냅한다.
- 켜기/끄기와 Alt를 누르는 동안 일시 해제를 제공한다.
- 스냅은 이동할 때만 작동한다. 가구 크기 편집 확인 자체가 자동 정렬을 일으키지 않는다.
- 그룹은 상대 위치를 유지하며 함께 이동한다. 가구 크기·도면 축척을 변경하지 않는다.
- 확대 상태에서도 과도하게 달라붙지 않는 허용 범위를 적용하고 경계 보정과 충돌하지 않게 한다.

### D3. 가구 옆 빠른 편집 — 다음 버전 확정

사용자는 사이드바까지 이동해 숫자를 바꾸는 번거로움을 줄이고 싶다. 우클릭 메뉴에 '가구 편집'을 제공하고 누르면 해당 가구 옆에 작은 창이 열려 이름·크기 등을 수정하고 확인 즉시 적용한다. 더블클릭으로 같은 편집창에 바로 진입하는 제안도 수락했다.

- 한 번 클릭: 선택 및 간격 표시.
- 드래그: 이동.
- 더블클릭: 가구 옆 빠른 편집창.
- 우클릭 → 가구 편집: 동일한 편집창.
- 필드: 이름, 사각형/원형, 가로·세로 또는 지름(mm), 확인·취소. X/Y는 노출하지 않는다.
- 그룹·벽 여유 공간 등 추가 설정은 기존 사이드바에 남긴다. 사이드바 편집은 보조 경로로 유지한다.
- 확인 또는 Enter: 검증 후 도면 이름·실제 도형 크기·오른쪽 목록에 즉시 반영한다. 별도 정렬이나 사이드바 적용을 요구하지 않는다.
- 취소 또는 Esc: 기존 확정값 유지.
- 창 바깥 클릭 또는 가구 드래그 시작: 미확정 입력을 버리고 창 닫기. 가구 자체는 유지한다.
- 잘못된 이름·치수는 창 안에 오류를 표시하고 수정 가능 상태를 유지한다.
- 창은 대상 가구를 가리지 않게 옆에 표시하며 화면 가장자리에서는 반대쪽으로 연다. 확대·스크롤 시 잘림도 방지한다.
- 크기 수정만으로 위치를 자동 정렬하지 않는다. 크기 증가로 경계를 넘으면 B1과 일관된 복구·안내 규칙을 정하고 기록한다.
- 단일 클릭의 서버 재렌더가 더블클릭 인식을 끊지 않도록 이벤트 순서를 검증한다.
- 입력 중 Enter 확정과 한글 조합 입력(IME), Delete/Backspace 보호를 확인한다.
- 확인한 값은 재편집·이동·호실 왕복·파일 저장/복원 뒤에도 유지돼야 한다.

### D4. 빈 도면 우클릭으로 샘플 가구 추가 — 확정

- 데스크톱에서 호실 도면 안의 가구 없는 곳을 우클릭하면 '샘플 가구 추가' 메뉴를 표시한다.
- 메뉴 항목을 선택했을 때만 한 개 생성한다. 우클릭 자체나 메뉴 취소로 생성하지 않는다.
- 우클릭 당시 도면 좌표를 기준으로 기본 사각형 샘플을 배치한다. 기존 기본값 1200×600 mm와 작은 방 보정 정책을 재사용한다.
- 생성 후 해당 가구를 선택한다. 더블클릭 또는 우클릭 편집으로 D3 창을 열 수 있다.
- 가장자리는 도면 안쪽으로 보정한다. 확대·스크롤 뒤에도 실제 mm 좌표가 일치해야 한다.
- 가구 위 우클릭은 기존 가구 편집·복사·회전·삭제 메뉴를 연다. 앱 여백 등 도면 밖에는 샘플 추가 메뉴를 열지 않는다.
- 메뉴 선택 이벤트가 뒤 도면에 전달되어 중복 생성되지 않게 한다. 다른 호실로 바뀌면 이전 메뉴와 생성 좌표를 폐기한다.
- 모바일 탭 생성 방식은 이번 요구로 바꾸지 않는다.

## 2. 반드시 해결할 사용자 제보

### B1. 도면 밖으로 끌면 가구가 화면에서 사라짐

재현: 가구 생성 → 도면 경계 밖으로 드래그 → 손을 놓으면 가구가 보이지 않거나 다시 잡을 수 없음.

요구: 가구가 사라지거나 접근 불가능해지지 않아야 한다.
대화에서 제안한 기본 해결안: 드래그 중에는 포인터를 따르고, 놓을 때 가구 전체가 들어가는 가장 가까운 도면 안쪽 위치로 보정한다.
- 방보다 큰 가구는 실제 입력 치수를 줄이지 않는다. 보이는 기준 위치에 두고 크기 초과를 표시한다.
- 회전된 사각형과 원형의 실제 경계를 반영한다.
- 그룹 이동은 상대 위치를 유지한 채 함께 보정한다. 그룹 전체가 방보다 크면 배치를 왜곡하지 않고 복구 가능한 위치와 안내를 제공한다.
- 확대·스크롤 상태에서도 포인터와 실제 mm 좌표 변환을 유지한다.
- 밖에서 손을 떼거나 pointercancel이 발생해도 영구 유실되지 않게 한다.
- 보정은 벽 경계만 처리하며 다른 가구와의 겹침을 숨기거나 자동으로 크기를 바꾸지 않는다.
정확한 경계 처리 구현은 개발 시 검증하되 위 요구를 만족해야 한다.

### B2. 복사 이름에 '복사'가 계속 누적됨

현재: 가구 → 가구 복사 → 가구 복사 복사.
요구: 숫자로 구분하고 복사본을 다시 복사해도 번호가 중첩되지 않게 한다.
대화에서 제안한 규칙:
- 책상 → 책상 2 → 책상 3. 기존 원본 이름을 강제로 바꾸지 않는다.
- 책상 2를 복사해도 책상 2 복사가 아니라 다음 사용 가능한 구분 번호를 부여한다.
- 같은 기본 이름의 기존 번호를 확인해 충돌을 피한다. 번호 탐색 범위와 삭제된 번호 재사용 규칙은 구현 시 정해 기록한다.
- 기존 '복사 복사' 이름 호환 처리도 검토하되 불러오기만으로 사용자 이름을 일괄 변경하지 않는다.
- 가구 ID는 표시 이름과 독립적으로 유지한다.

### B3. 가구 개수 집계는 구분 번호와 양끝 공백을 무시

사용자 명시: 책상1과 책상2는 같은 책상으로 계산하고 이름 앞뒤 공백도 무시한다.
예: '책상', '책상1', '책상 2', ' 책상3 ' → 책상 총 4개.
- 도면의 개별 이름은 보존하고 집계용 기본 이름을 따로 정규화한다.
- 앞뒤 공백을 제거하고 끝에 붙은 구분 번호 및 그 앞 공백을 제외한다.
- '2단 수납장'과 '3단 수납장'처럼 이름 본문에 들어간 숫자는 제거하지 않는다.
- '모델 1200'처럼 의미 있는 말미 숫자와 자동 번호의 구분은 애매할 수 있다. 자동 생성 번호의 메타데이터 분리 등으로 향후 충돌을 줄이되 사용자 예시는 반드시 만족한다.
- 복사·이름 변경·삭제·호실 전환 직후 요약을 갱신한다.
- 치수가 다른 동일 기본 이름은 사용자가 요청한 기본 이름 총계에서 누락시키지 않는다. 치수별 상세 구분은 보조 정보로만 검토한다.

### B4. 모바일 이름·크기 수정 후 '적용'이 제대로 반영되지 않음 — 미해결, 다음 버전 제외

재현: 모바일에서 가구 터치 → 이름 또는 크기 변경 → 적용 → 도면에 제대로 반영되지 않음.
원인은 아직 확인하지 않았다. 입력 전달 실패, 폼 검증, 트리거 처리, Streamlit 재렌더, 이전 위젯 상태 덮어쓰기는 조사 후보일 뿐 확정 원인이 아니다.
후속 모바일 버전에서 UI 재구성과 함께 실제 데이터 반영 경로를 수정한다. 겉모양만 바꾸고 해결로 간주하지 않는다.

합격 기준:
- 적용 직후 도면 이름과 실제 도형 치수가 변경된다.
- 목록과 이름별 수량이 함께 갱신된다.
- 편집창을 다시 열면 확정값이 표시된다.
- 이동·호실 왕복 후에도 새 값이 유지된다.
- 저장/불러오기 후에도 새 값이 유지된다.
- 취소 또는 적용 전 드래그는 미확정 입력만 폐기한다.
- 가상 키보드가 열린 상태, 입력 포커스 유지 상태에서도 적용이 동작한다.
- 잘못된 값은 오류를 표시하고 기존 정상 데이터를 유지한다.
- 모바일 실기기 확인이 불가능하면 합성 이벤트 검증과 명확히 구분해 보고한다. 과거 데스크톱/DOM 통과를 모바일 정상 동작의 증거로 대체하지 않는다.

## 3. 이전 사용성 후보 기록 — 이번 범위는 최상단 확정 목록만 적용

사용자가 승인한 중심 방향은 사용성·편의성 우선이다. 아래 세부 항목은 대화에서 제안한 다음 빌드 후보이며, 구체 범위는 개발 시 버그 수정과 함께 현실적으로 묶는다.

1. 실행 취소·다시 실행: 이동/편집/복사/삭제를 복구, 그룹 이동은 한 단계. Ctrl+Z와 모바일 되돌리기 제공.
2. 선택·이동·편집 안정화: 잡은 지점 유지, 도면 축척 고정, 메뉴·스크롤·확대 제스처 충돌 방지.
3. 모바일 선택 메뉴 재구성: 선택 시 작은 편집/회전/복사/삭제 메뉴, 치수 입력 때만 확장. 자주 쓰는 동작을 위해 긴 페이지를 오가지 않도록 한다. 드래그 시작 시 편집창만 닫힌다.
4. 간격 표시·정렬 보조: 선택/이동 중 가까운 벽·가구와의 간격과 정렬선. 스냅은 쉽게 끌 수 있고 내부 좌표 정밀도를 유지한다.
5. 빠른 복사·반복 배치: 같은 치수 재입력 감소. 데이터베이스 준비 없이 동작해야 한다.
6. 목록 선택·잠금: 작은 가구를 목록에서 선택하고 확정 가구의 실수 이동을 방지한다.

빈 도면 탭 생성과 길게 누르기 흔들림+× 삭제는 기존 요구다. 다른 조작 모드로 자동 대체하지 않는다. 삭제 버튼 등 눈에 보이는 보조 경로는 추가 검토한다.

## 4. 기존 결정과 품질 기준

- 고정 PDF의 2·3페이지 기반 기존 23개 호실을 사용한다. 신규 도면 업로드/진하기 UI를 다시 추가하지 않는다.
- 데스크톱 좌측 추가·편집·호실 치수, 우측 소형 가구 요약, 하단 저장/불러오기 구조를 유지하며 다듬는다.
- X/Y 직접 입력은 다시 노출하지 않는다. 사용자 치수는 정수, 내부 계산과 저장은 기존 정밀도를 유지한다.
- 원형/사각형, 이름 아래 치수, 그룹 이동, Delete 입력 보호, 호실 왕복 상태, v1/v2 파일 읽기를 보존한다.
- 방 공칭치수와 실제 내부 유효치수의 차이가 있다. 현재 충돌 판정이 문 열림·기둥까지 보장하지 않으므로 '배치 가능'을 절대적 현장 적합성으로 표현하지 않는다.
- 관련 버그는 개발자가 능동 점검한다. 기능 추가에 앞서 제보 재현과 상태 흐름을 확인한다.
- 구조 분리와 단일 상태 관리, 이벤트 수명 정리, 중복 명령 방지 등 유지보수성을 지킨다.
