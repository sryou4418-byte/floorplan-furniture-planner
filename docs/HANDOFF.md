- 수도·전기·전기 3상 점은 도면에서 드래그해 위치를 바꿀 수 있어야 한다.

## 2. 프로젝트 전체 맥락과 유지할 결정

사용자는 실제 도면 위에 단순한 가구를 놓고, 직접 입력한 치수로 방 대비 크기와 배치 가능 여부를 확인하려 한다. Python 개발을 원했고, 미국증시위험 프로그램과 별개 GitHub 저장소 및 공개 Streamlit 앱으로 만들었다.

- 가구는 사각형 또는 원형. 이름 아래 사이즈 표시. 모든 모델 좌표·치수는 mm이며 화면 확대와 독립적이다.
- 가구는 드래그로 이동하고 같은 그룹 이름을 가진 가구는 함께 이동한다. 데스크톱 Shift 다중 선택 및 Delete/Backspace 삭제를 유지한다. 텍스트 입력 중 삭제키는 가구를 삭제하면 안 된다.
- 사용하는 도면은 `AA-100 성환고등학교 임시교사 구축 시설공사.pdf` 하나. 2페이지 1층, 3페이지 2층을 기준으로 호실 23개를 분리했다. 1페이지는 참고만 한다.
- 기존 저장소의 호실 이미지·프리셋을 재사용한다. PDF 원본·1페이지·층 전체 도면을 새로 공개하지 않는다. 사용자가 도면 업로드와 진하기 조절 UI를 제거하라고 했으므로 다시 추가하지 않는다.

- 화면 전체를 활용하되 비율을 유지하고 사용자가 배율을 조절할 수 있어야 한다. 도면이 지나치게 커서 불필요한 스크롤이 생기지 않게 한다.
- 매 빌드 변경 내역과 검증·잔여 문제를 GitHub에 기록해 다음 수정에 사용한다.

## 3. 다음 빌드 확정 요구사항 — 최우선

### M1. 모바일 빈 도면 탭 → 샘플 가구 즉시 생성

- 모바일/터치에서 가구가 없는 도면 위치를 짧게 탭하면 그 위치에 샘플 가구 1개를 생성한다. 별도의 추가 폼 제출을 요구하지 않는다.
- 이름·기본 치수는 미지정이다. 구현 기본안은 사각형 `샘플 가구`, 1200×600 mm. 도면 가장자리에서는 방 안으로 보정하고 작은 방에서는 들어갈 기본 크기를 정한다. 채택한 규칙을 기록한다.
- 손가락 스크롤/드래그/핀치, 길게 누르기, 가구 탭, 메뉴·× 버튼 탭을 빈 도면 탭으로 처리하지 않는다. 한 번 탭에 하나만 생성한다.
- 화면 좌표를 실제 도면 mm 좌표로 변환한다. 배율·페이지 스크롤·브라우저 UI 높이 변화에도 생성 위치가 맞아야 한다.

### M2. 생성된 가구 탭 → 편집 UI

- 가구를 짧게 탭하면 이름 변경, 원형/사각형 선택, 크기 직접 입력이 나온다. 사각형은 가로·세로, 원형은 지름. 단위 mm를 명시한다.
- 기존 회전·복사 등의 기능은 접근 가능하게 유지하고 원형 회전은 비활성화한다.
- 이름 빈값/길이 제한, 0·음수·비정상 숫자 등을 검증한다. 원형은 모델의 가로와 세로가 같은 지름이어야 한다.
- 확인/취소와 미확정 입력 처리 규칙을 명확히 한다. 권장안: 적용 버튼으로 확정, 취소·드래그 시작 시 미확정 입력은 버리고 이미 확정한 값은 유지. 최종 채택 동작을 사용자에게 알린다.
- 작은 화면과 가상 키보드에서 필드와 적용/취소가 가려지지 않아야 하며, 편집 UI가 가구 드래그를 막아서는 안 된다.

### M3. 드래그 시작 → 편집창 자동 닫힘 + 가구 이동

사용자의 정정 원문 의미: “생성된 가구를 터치로 끌고갈 때 이름변경 같은 창이 자동으로 사라지고 가구가 움직여야 한다.”

- **사라지는 것은 편집창이지 가구가 아니다.** 가구 삭제/숨김/스와이프 삭제를 구현하지 않는다.
- 편집창이 열린 상태에서도 가구를 잡아 끌 수 있어야 한다. 드래그가 시작되면 창이 닫히고 잡은 지점 기준으로 자연스럽게 이동한다.
- 탭·드래그·길게 누르기를 이동 임계값과 타이머로 구분한다. 드래그 후 손을 떼었을 때 편집창이 다시 열리거나 샘플 가구가 생성되면 안 된다.
- 그룹 이동과 좌표 입력 동기화를 유지하고 pointercancel/캡처 해제/렌더 재실행 때 가구가 사라지거나 튀지 않게 한다.

### M4. 모바일 길게 누르기 → 흔들림 + × 삭제

- 가구를 길게 누르면 흔들리는 시각 효과와 눌러 삭제하는 × 버튼을 표시한다. 길게 누르기 자체로 삭제하지 않는다.
- 이는 v0.3의 “길게 누르면 우클릭 메뉴” 동작을 모바일에서 대체한다. 데스크톱 우클릭 메뉴는 유지한다.
- ×에는 충분한 터치 영역(최소 44px 권장)과 삭제 접근성 이름을 제공한다. 작은 가구나 화면 가장자리에서도 누를 수 있어야 한다.
- ×로 삭제할 때 뒤 도면에 탭이 전달되어 새 가구가 생기면 안 된다.
- 권장안: 길게 누른 가구만 삭제 대상으로 표시하고 바깥 탭/완료로 모드 종료. 그룹 전체 일괄 삭제는 사용자 요구가 아니다.
- 흔들림은 위치 좌표를 변경하지 않는 시각 효과로 구현하고 동작 줄이기 설정을 고려한다.

### M5. 모바일 상단 제목 잘림 수정 — 사용자 스크린샷 확인

- `IMG_1907.jpeg`: 아이폰 Safari 화면에서 상단 “도면 가구 배치” 제목이 일부만 보이고 아래 호실 선택창과 겹쳐 보인다.
- 화면상 잘림은 확인했지만 정확한 CSS/브라우저 원인은 아직 진단하지 않았다. 제목 줄 높이, 부모 높이/overflow, Streamlit 고정 헤더, 상단 여백, safe-area, 스크롤 위치를 확인한다.
- 제목·호실 선택창·도구 모음이 겹치지 않게 수정한다. 여백을 과도하게 늘려 도면이 다시 작아지지 않도록 균형을 맞춘다.
- iPhone Safari 주소창 펼침/접힘, 세로/가로 전환, 키보드 표시, 스크롤 복귀 상태를 점검한다.

### M6. 사이드바 열 때 호실 목록 자동 닫힘 — 사용자 스크린샷 확인

- `IMG_1908.png`: 호실 선택 목록을 펼친 뒤 왼쪽 사이드바를 열면 목록이 닫히지 않고 사이드바 위에 남아 저장/불러오기 영역을 가린다.
- 재현 순서: 호실 선택창 열기 → 상단 왼쪽 사이드바 열기 → 목록 잔류 확인.
- 사이드바를 여는 순간 목록을 닫는다. 목록 바깥 탭으로도 닫히며 선택한 호실 값은 바뀌지 않아야 한다.
- 단순히 z-index로 뒤에 숨겨 열린 상태를 남기지 않는다. 포커스·팝업 수명 관리까지 확인한다.
- 스크린샷은 대화에서 확인했지만 원본 이미지는 GitHub에 올리지 않았다. 문서의 재현 절차만으로 시작 가능하다. 로컬 첨부 경로는 지속 접근을 보장하지 않으므로 의존하지 않는다.

## 4. 추가 버그 점검도 개발자 책임

사용자는 “그 외에 버그가 있는지 확인하고 제거하는 것은 너의 몫”이라고 명시했다. 위 항목만 수정하고 끝내지 말고 관련 흐름을 능동적으로 검증한다. 아래는 **점검 대상**이며 모두 실제 발견된 버그라는 뜻은 아니다.

- 빠른 연속 탭/더블 탭으로 중복 생성·삭제·명령 재실행.
- 터치 이동·페이지 스크롤·확대 조작과 샘플 생성의 충돌.
- 길게 누르기 타이머가 드래그/호실 전환/취소 뒤 남는 현상.
- 선택 가구 삭제 후 오래된 선택 ID와 편집 필드가 남는 현상.
- 이름·모양·치수 편집 후 이전 Streamlit 위젯 값이 새 값을 덮는 현상.
- 호실 전환 직전/직후 지연 이벤트가 다른 호실에 적용되는 현상.
- SVG 확대 상태의 생성/드래그 좌표 오차, 그룹 이동 시 누적 오차.
- 방보다 큰 가구, 원↔사각 전환, 회전 후 벽 이탈/겹침 판정.
- 저장 직전 최신 변경 누락, 모든 호실 파일 복원, 기존 v1 파일 호환.
- 손상된 파일·크기 초과·비정상 숫자와 이름에 HTML 같은 문자가 들어오는 경우의 안전 처리.
- 여러 UI 패널/팝업 동시 표시, 키보드 포커스, 모바일 닫기/뒤로가기·가상 키보드.
- 재렌더마다 중복 이벤트 리스너, 유실된 pointer capture, 중복 트리거, 배포 후 이전 작업판 캐시.

## 5. 구조와 구현 시 주의점

`app.py`는 UI/세션과 콜백, `planner/canvas.py`는 Streamlit v2 커스텀 컴포넌트의 HTML/CSS/JS/SVG, `planner/actions.py`는 가구 명령이다. `planner/workspace.py`는 호실별 상태와 전체 파일, `models.py`는 데이터, `geometry.py`는 mm 기반 판정을 담당한다. 상세는 DEVELOPMENT 참고.

- `workspace.project`와 `st.session_state.project`는 현재 호실의 동일 객체여야 한다. 재방문 때 프리셋을 다시 적용하지 않는다.
- 현재 canvas 이벤트는 `room_key`와 nonce를 보낸다. 앱은 다른 호실의 이벤트를 무시한다. 새 생성/편집 이벤트에도 같은 보호를 적용한다.
- 현재 JS는 `getScreenCTM().inverse()`로 좌표 변환, AbortController와 ResizeObserver 정리를 사용한다. 기존 리스너 정리를 보존한다.
- 현재 모바일은 550ms 길게 누르기, 6px 이동 임계값으로 구분한다. 수치는 시작점일 뿐이며 실제 사용성을 확인한다.
- v0.3 작업판 버전 상수 `CANVAS_VERSION`, 등록 이름 `floorplan_furniture_canvas_v03`, app 버전 비교 재로드가 있다. 다음 빌드에서 관련 버전을 일치시킨다. 공개 배포에서 이전 컴포넌트가 남았던 이력이 있다.
- 기존 메뉴 텍스트는 textContent로 표시한다. 입력 이름을 HTML로 삽입하지 않는다.
- 공개 저장소에 비밀키/인증값을 추가하지 않는다. 새로운 데이터베이스나 다른 서비스로 이전할 필요는 없다.
- 이전 환경에서는 GitHub 커넥터로 커밋을 만들었으므로 로컬/원격 커밋 ID가 다를 수 있다. 새 세션은 최신 remote를 기준으로 변경을 확인하고 force push하지 않는다.
